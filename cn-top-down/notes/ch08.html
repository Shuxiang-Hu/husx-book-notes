08 · Security in Computer Networks

Network security is built on cryptographic primitives — symmetric and public-key encryption, hash functions, and digital signatures — that enable confidentiality, integrity, and authentication across every layer of the protocol stack.

Security Goals and Threat Model

A secure communication channel must provide:

  • Confidentiality — only sender and intended receiver understand the message (encryption).
  • Message integrity — message has not been altered in transit (cryptographic hash + MAC).
  • End-point authentication — sender and receiver can confirm each other's identity.
  • Operational security — protection against attacks on the network itself (firewalls, IDS).

The canonical threat model assumes an active intruder (Trudy) who can intercept, modify, inject, and replay messages. Passive attacks (eavesdropping) are addressed by encryption; active attacks require integrity protection and authentication.

Principles of Cryptography

Symmetric key cryptography: both parties share the same secret key Ks. The same key encrypts and decrypts. Modern algorithms: AES (128/256-bit blocks), DES (now broken), 3DES. Key strength comes from block cipher design and key length, not algorithm secrecy (Kerckhoffs's principle).

Public key cryptography: each entity has a public key K+ (openly published) and a private key K− (secret). Encrypting with K+ can only be decrypted with K−. RSA is the dominant algorithm. Security relies on the difficulty of factoring large integers. Computationally expensive — in practice, used to establish symmetric session keys, not for bulk data encryption.

Message Integrity and Digital Signatures

A cryptographic hash function (SHA-256, SHA-3) maps an arbitrary-length message to a fixed-length digest. Properties: deterministic, fast to compute, pre-image resistant, collision resistant (computationally infeasible to find two messages with the same digest).

A Message Authentication Code (MAC) authenticates both the message and sender: MAC = H(message + s) where s is a shared secret. Used in HMAC (HMAC-SHA256). Provides integrity without non-repudiation.

Digital signatures provide non-repudiation. Sender signs with private key K−: sign = K−(H(message)). Receiver verifies with K+: check that K+(sign) == H(message). A valid signature proves the sender held the private key and signed this exact message. RSA and ECDSA are common algorithms.

TLS: Securing the Web

TLS (Transport Layer Security, formerly SSL) provides a secure channel over TCP, used by HTTPS. The TLS handshake establishes:

  1. Server sends certificate (public key + CA signature).
  2. Client verifies certificate chain against trusted CAs.
  3. Client generates a pre-master secret, encrypts with server's public key.
  4. Both derive session keys (master secret → symmetric keys for encryption + MAC).
  5. All subsequent data is encrypted with AES-GCM or ChaCha20-Poly1305.

TLS 1.3 (2018) eliminates RSA key exchange in favor of Diffie-Hellman (for forward secrecy), reduces handshake to 1 RTT (or 0-RTT for resumption), and removes weak cipher suites.

Network-Layer Security: IPsec and Firewalls

IPsec provides network-layer security: authentication (AH — Authentication Header) and confidentiality + authentication (ESP — Encapsulating Security Payload). Two modes: transport mode (between end systems, encrypts payload only) and tunnel mode (between gateways, encrypts entire original IP datagram — used for VPNs). IKE protocol establishes the Security Association (SA) defining keys and algorithms.

Firewalls inspect and filter traffic at the network perimeter. Stateless packet filters check individual packet headers. Stateful filters track TCP connection state. Application gateways (proxy firewalls) inspect application-level content (e.g., HTTP, SMTP). IDS/IPS (Intrusion Detection/Prevention Systems) perform deep packet inspection, matching traffic against attack signatures.
