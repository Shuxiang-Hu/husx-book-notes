03 · Transport Layer

The transport layer provides logical communication between application processes on different hosts — multiplexing and demultiplexing data streams, with TCP adding reliable, ordered delivery and congestion control on top of an unreliable IP network.

Multiplexing and Demultiplexing

The transport layer extends the network-layer's host-to-host delivery to a process-to-process delivery. Multiplexing at the sender: gather data from multiple sockets, add transport headers. Demultiplexing at the receiver: deliver incoming segments to the right socket.

A socket is identified by a four-tuple: (source IP, source port, destination IP, destination port). UDP sockets are identified only by destination IP and port — all UDP segments with the same destination are delivered to the same socket. TCP sockets use all four fields, allowing multiple clients to connect to the same server port.

UDP: Connectionless Transport

UDP provides a bare-bones transport: multiplexing/demultiplexing, and optional error detection (via a 16-bit checksum). It is connectionless — no handshake, no state, no guaranteed delivery, no ordering. The UDP segment header has only 4 fields (source port, destination port, length, checksum) totaling 8 bytes.

Why use UDP? It is faster (no connection establishment delay), no congestion control (important for real-time streaming), and the application has full control over timing. DNS, streaming media, QUIC, and online gaming all use UDP.

Reliable Data Transfer: Principles

The challenge: IP delivers packets unreliably (lost, corrupted, reordered). TCP must impose reliability on top. The key mechanisms developed incrementally:

  • rdt 1.0 — perfect channel (baseline)
  • rdt 2.x — bit errors: ACK/NAK, retransmit on NAK. Problem: corrupted ACK/NAK.
  • rdt 3.0 — adds sequence numbers and timeout-based retransmission. Correct but slow (stop-and-wait).
  • Pipelining (Go-Back-N, Selective Repeat) — allow multiple outstanding unacknowledged packets.

TCP: Connection-Oriented Transport

TCP is connection-oriented: a three-way handshake establishes state at both endpoints before data flows. TCP provides:

  • Reliable, ordered delivery — sequence numbers + cumulative ACKs + retransmission.
  • Flow control — receiver advertises a receive window (rwnd) limiting how much the sender can have outstanding.
  • Full-duplex — data flows in both directions over the same connection.

TCP uses adaptive retransmission: the timeout is set to EstimatedRTT + 4·DevRTT, tracking the smoothed RTT with exponential weighted moving average.

Connection teardown uses a four-way handshake: FIN → ACK → FIN → ACK, allowing each direction to close independently.

TCP Congestion Control

TCP controls congestion by maintaining a congestion window (cwnd) that limits total outstanding data. The key algorithm phases:

  • Slow Start — cwnd starts at 1 MSS, doubles each RTT until threshold (ssthresh) or loss.
  • Congestion Avoidance — cwnd grows linearly (1 MSS per RTT). When loss detected: ssthresh = cwnd/2.
  • Fast Retransmit — 3 duplicate ACKs trigger immediate retransmit without waiting for timeout.
  • Fast Recovery — TCP Reno: cwnd = ssthresh + 3 after triple dup-ACK; TCP Tahoe: drops to 1 MSS.

TCP's throughput averages roughly 0.75 · MSS / (RTT · √p) where p is the packet loss rate — an insight called the TCP throughput formula.
