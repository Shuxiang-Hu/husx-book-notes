02 · Application Layer

The application layer is where network applications live — HTTP for the Web, SMTP for email, DNS for name resolution — each defined by a protocol governing message formats and the actions of communicating processes.

Network Application Architectures

Modern network applications are structured in one of two dominant ways. In the client-server architecture an always-on server with a stable, well-known address responds to requests from many clients. The server scales using data centers with thousands of virtual servers. In a P2P architecture peers directly communicate with each other without a dedicated server, allowing the system to self-scale as more peers join.

The interface between an application and the transport layer is the socket — analogous to a door between the application process and the network. A process is identified by its IP address plus a port number.

HTTP: The Web's Protocol

HTTP (HyperText Transfer Protocol) is the application-layer protocol of the Web. It is stateless — the server maintains no information about past client requests. HTTP uses TCP as its transport; a client initiates a TCP connection to port 80, then sends HTTP request messages and receives HTTP response messages.

Non-persistent HTTP opens a new TCP connection for each object — incurring a 2-RTT overhead per object. Persistent HTTP (default in HTTP/1.1) reuses the same TCP connection, and HTTP/1.1 also supports pipelining for multiple back-to-back requests.

HTTP/2 introduces binary framing, header compression (HPACK), stream multiplexing over a single TCP connection, and server push, dramatically reducing latency for modern web pages.

DNS: The Internet's Directory Service

The Domain Name System (DNS) is a distributed database implemented as a hierarchy of DNS servers. It translates human-readable hostnames (e.g., www.example.com) into IP addresses. DNS also provides other services: mail server aliasing (MX records), load distribution via multiple IP addresses per hostname, and canonical name aliasing (CNAME).

The hierarchy has three classes: root DNS servers (13 clusters worldwide), top-level domain (TLD) servers (for .com, .org, .edu, country codes), and authoritative DNS servers (maintained by organizations for their domains). A local DNS server (resolver) acts as a proxy cache, performing iterative or recursive queries on behalf of hosts.

Peer-to-Peer File Distribution

In P2P file distribution (e.g., BitTorrent), each peer receiving chunks of a file simultaneously uploads chunks to other peers. The distribution time scales well: as more peers join, the aggregate upload capacity grows. BitTorrent uses a rarest-first policy (prioritize the least-replicated chunks) and a tit-for-tat incentive mechanism (unchoke peers who provide data at the highest rate).

The time to distribute a file of size F to N peers in client-server mode is proportional to N (server bottleneck), whereas P2P distribution time grows as O(F/u_s + F/d_min + F·N/u_total), meaning it scales far better for large N.

Video Streaming and CDNs

DASH (Dynamic Adaptive Streaming over HTTP) stores a video in multiple quality levels (bitrates). The client periodically measures available bandwidth and selects the chunk quality that avoids stalling. Netflix and YouTube both use forms of DASH.

Content Distribution Networks (CDNs) replicate content across many geographically distributed servers (clusters). When a user requests content, DNS is used to redirect them to a nearby cluster. CDNs use two placement strategies: Enter Deep (deploy clusters close to users in ISPs) and Bring Home (fewer but larger clusters at IXPs).
