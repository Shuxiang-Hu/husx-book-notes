04 · The Network Layer: Data Plane

The network layer moves packets from one router to the next along a path — the data plane performs per-packet forwarding based on routing table entries, while IP provides the universal addressing and datagram format that ties the Internet together.

Forwarding vs Routing: Two Planes

The network layer has two key functions that map to two planes:

  • Data plane (forwarding) — local, per-router function. When a packet arrives at a router's input port, the router moves it to the appropriate output port. This is fast-path hardware (nanoseconds).
  • Control plane (routing) — network-wide logic. Determines the end-to-end path a packet takes from source to destination. This is slow-path software (milliseconds) — runs routing algorithms (Chapter 5).

Forwarding uses a forwarding table (or flow table in SDN) that maps destination addresses (or header fields) to output links. The network service model is best-effort: no bandwidth or delay guarantees, no ordering guarantee, no reliability.

Router Architecture

A modern router has four key components: input ports, a switching fabric, output ports, and a routing processor. Input ports perform line termination, link-layer processing, and packet lookup (longest-prefix match). The switching fabric connects input to output ports — three architectures exist: memory, bus, and crossbar (interconnection network). Output ports perform queuing, packet scheduling, and line-termination.

Head-of-line (HOL) blocking occurs with input queuing: a packet at the head of an input queue blocks packets behind it even if their output ports are free. Modern high-speed routers use virtual output queuing (VOQ) to mitigate HOL blocking.

IP: The Internet Protocol (IPv4)

IP datagrams have a 20-byte base header (plus options). Key fields: version (4 bits), header length, type of service, total length (max 65,535 bytes), identification/flags/fragment offset (for fragmentation), TTL (decremented by each router; datagram dropped at 0), protocol (6=TCP, 17=UDP), header checksum, source/destination IP addresses.

Fragmentation: if a datagram is larger than the MTU of the next link, the router fragments it. Reassembly happens only at the destination host. IPv6 eliminates router-level fragmentation.

IP Addressing and Subnets

An IP address is a 32-bit number, written in dotted-decimal notation (e.g., 192.168.1.1). Addresses are assigned to interfaces, not to hosts. A subnet is a set of device interfaces that can physically reach each other without an intervening router — defined by an address/prefix-length (e.g., 192.168.1.0/24, mask = 24 bits). CIDR (Classless Inter-Domain Routing) replaced the old classful (A/B/C) scheme and allows arbitrary prefix lengths.

DHCP (Dynamic Host Configuration Protocol) auto-assigns IP addresses to hosts when they join a network — a discover/offer/request/ACK four-step exchange using UDP broadcast.

IPv6

IPv6 uses 128-bit addresses (written as eight 16-bit hexadecimal groups), solving IPv4 address exhaustion. The IPv6 header is a fixed 40 bytes — simpler than IPv4 (no checksum, no fragmentation at routers). Key new features: flow labels for differentiated services, anycast addresses, mandatory IPsec support, auto-configuration (SLAAC). Transition from IPv4 uses tunneling: IPv6 datagrams are encapsulated inside IPv4 datagrams across IPv4-only segments.

Generalized Forwarding and SDN

Traditional IP forwarding uses only the destination IP address. Generalized forwarding (OpenFlow) allows matching on any combination of header fields (IP source/dest, TCP/UDP ports, MAC addresses, VLAN ID, etc.) and then taking actions: forward, drop, modify header, or flood.

In SDN, a remote controller computes and installs flow table entries in routers (now called packet switches). This decouples the control plane from the data plane, enabling programmable, software-defined network behavior.
