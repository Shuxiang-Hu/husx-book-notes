Part II — Distributed Data

Chapter 9 · Consistency & Consensus

Chapter 8 cataloged what can go wrong in distributed systems. This chapter asks: given those constraints, what guarantees can we actually provide? It covers the strongest consistency guarantee (linearizability), why it conflicts with availability (CAP), ordering guarantees (causality, total order), and the consensus problem that underpins leader election and atomic commits.

Consistency Guarantee Spectrum

Linearizability

Linearizability (also called atomic consistency or strong consistency) makes a distributed system appear to behave like a single copy of the data, with all operations appearing to take effect at a single point in time.

When do you need Linearizability?

Use CaseWhy Linearizable?
Leader election (ZooKeeper)Only one node should believe it is leader — requires atomic compare-and-set on a single register
Uniqueness constraints (username, booking)Two users picking same username must be rejected; needs atomic check-and-set
Cross-channel ordering (Alice + Bob via diff paths)If Alice updates then messages Bob, Bob must see Alice's update (requires causally + linearizable)
Counters, sequence numbersNeed linearizable increment to avoid duplicates
User profile readsEventual consistency usually fine — stale for a few seconds is acceptable

CAP Theorem

Brewer's CAP theorem (2000, formally proved by Gilbert & Lynch 2002): a distributed data store can guarantee at most two of:

  • Consistency — Linearizability (not ACID consistency)
  • Availability — every request receives a response (not an error)
  • Partition tolerance — the system continues to operate if network partitions occur

Since network partitions will occur in any distributed system, the real choice is between CP (consistent, partition-tolerant) and AP (available, partition-tolerant). CA is not a useful option for distributed systems.

CAP is often misunderstood — Kleppmann argues it's a poor framework. "Consistency" means linearizability (not ACID's C). "Availability" means every request gets a response (not a specific response). The theorem only applies during partition events. Most systems are not cleanly CP or AP.

Ordering & Causality

Total Order vs Causal Order — Causality is a partial order (some events have no causal relation and are concurrent). Linearizability provides a total order — every pair of operations has a defined order. Total order broadcast (atomic broadcast) is equivalent in power to consensus.

Distributed Consensus

Consensus: getting multiple nodes to agree on a single value. Formally requires:

  • Uniform agreement: no two nodes decide differently
  • Integrity: a node decides at most once
  • Validity: the decided value was proposed by some node
  • Termination: every non-crashed node eventually decides

Two-Phase Commit (2PC) — Atomic Commit

2PC is a "blocking" protocol — if the coordinator crashes after sending prepare but before sending commit/abort, participants holding locks are stuck. They cannot abort (they voted yes) and cannot commit (haven't received the directive). They must wait for the coordinator to recover — potentially for hours.

Key Takeaways

Linearizability
Makes a distributed system appear as a single copy. Expensive — requires synchronous coordination. Needed for leader election, uniqueness constraints, and cross-channel ordering.
CAP theorem
During a network partition, choose between consistency (linearizability) and availability. Partition tolerance is not optional; CA in a distributed system is not achievable.
Causal consistency
Strongest model achievable without coordination. Causally related operations appear in order; concurrent operations may appear in any order. Uses version vectors or Lamport clocks.
2PC
Provides atomic commit across multiple nodes but blocks if coordinator crashes. Used inside databases for distributed transactions; not a consensus algorithm.
Raft / Paxos
Fault-tolerant consensus. Tolerate f failures with 2f+1 nodes. Raft designed for understandability; Paxos is the theoretical foundation. Equivalent in power to total-order broadcast and linearizable storage.
