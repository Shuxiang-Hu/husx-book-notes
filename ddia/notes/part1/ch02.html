Chapter 2: Data Models and Query Languages

How we represent data — relational tables, JSON documents, property graphs — determines what queries are natural and what joins are painful.

The three dominant data models and their sweet spots.

§2.1

Relational Model vs Document Model

Edgar Codd proposed the relational model in 1970. Data is organized in relations (tables) and tuples (rows). SQL, developed in the 1970s, became the dominant query interface. For 25–30 years, relational DBs dominated — then NoSQL emerged around 2010.

NoSQL Drivers

  • Need for greater scalability (huge write throughput, very large datasets) than relational DBs can easily achieve.
  • Preference for free and open source software over commercial DBs.
  • Specialized query operations not well-supported by SQL.
  • Frustration with the restrictiveness of relational schemas.

Object-Relational Impedance Mismatch

Application code uses OO/functional languages with objects, lists, and nested structures. Relational DBs use tables with rows and columns. ORM frameworks (ActiveRecord, Hibernate) reduce boilerplate but can't hide the mismatch. The résumé example: a user has one record but many jobs, education entries, and contact methods — naturally a JSON tree. In SQL: either multiple tables with foreign keys (complex joins) or a JSON/XML blob column (can't query inside it easily).

Same résumé data: document model stores it as one JSON tree (good locality), relational needs multiple tables + joins.

Modern trend: convergence. PostgreSQL/MySQL support JSON columns. MongoDB 3.2+ supports joins. The boundary is blurring.
§2.2

Graph-Like Data Models

When many-to-many relationships are very common and complex, the relational model becomes awkward. Graph databases shine here: social networks, the web, road maps, knowledge graphs.

Property Graph Model

  • Vertices (nodes): unique ID, set of outgoing edges, set of incoming edges, collection of key-value properties.
  • Edges: unique ID, tail vertex, head vertex, label (relationship type), collection of key-value properties.
  • Any vertex can connect to any other — no schema restriction.

Property graph: vertices (people, places) connected by labeled, directed, property-bearing edges. Easy to express complex relationships.

Cypher Query Language (Neo4j)

Cypher uses ASCII-art pattern matching: (a:Person {name:'Alice'})-[:BORN_IN]->(b:Location). Declarative — the query optimizer finds the best execution plan. Much more natural for graph traversal than SQL with recursive CTEs.

Triple-Stores and SPARQL

All information stored as three-part statements: (subject, predicate, object). E.g., (Jim, age, 33) or (Jim, likes, bananas). The semantic web vision: a web of linked data. SPARQL is the query language. RDF (Resource Description Framework) for data interchange. Turtle syntax for human-readable triples.
